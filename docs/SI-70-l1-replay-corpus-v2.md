## What this slice delivers

### 1. Corpus v2 — `si/gaia/propose_measure.py`

`REPLAY_WORKLOADS_V2` runs six named workloads end to end
through `HearthProposer` + `run_task` against the labelled
replay transport, with all statistics folded **from the
journal**:

- **The SI-68 workloads, repeated verbatim** (same labels,
  same scripts) for comparability with
  `docs/SI-68-measurements.json`: `benign-read`,
  `injection-shaped`, `hallucinated-reference`.
- **A second fixture family** (SI-69 §4.3):
  - `multi-cycle-read` — a three-tool-cycle task (list →
    read → search → completion signal).
  - `depends-on-chain` — a valid `depends_on` batch chain.
    §9.3 stage 4 verifies each declared seq against the
    journal fold — only seqs of the same task's
    *already-journaled* intents verify — so a valid chain
    cannot be a static script. The fixture is therefore a
    labelled replay transport (`_ChainReplayTransport`,
    `is_replay` True, the replay transport label) that
    generates each response at call time, reading the prior
    intent seq from the perception the gateway request
    itself carries — exactly what a model would read — and
    declaring it in the next proposal (`requirement:
    "success"`, then `"outcome"`). A call whose perception
    names no prior intent raises a labelled failure instead
    of fabricating a chain.
  - `perception-truncation` — the benign read run with the
    proposer's §6.3 assembly bound set to 12,288 bytes
    (`proposer_max_perception_bytes` default is 256 KiB),
    so the §6.3 truncation order engages and every truncated
    element is labelled in the perception and carried into
    the §14 attempt record.

The runner additionally folds three L-1 acceptance
quantities from the journal: the §14 chain walk (via
`walk_attempt_chain`) for every gateway response and for
admitted batches specifically; the journaled `depends_on`
chain (self-edit rows with non-empty declared dependencies,
plus the responses' model-authored chaining counts); and
§6.3 truncation labels on attempt records, per workload.
