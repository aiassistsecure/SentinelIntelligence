## What this slice delivers

### 1. The measurement harness — `si/gaia/propose_measure.py`

S-7 pattern (§18.2 discipline): environment fingerprint,
named workloads, N and spread (`summarize`: median/min/max,
p95 nearest-rank only at N ≥ 30, empty input all-None —
never a fabricated number), statistics folded **from the
journal**, never from proposer memory.

- **Replay mode** (default): the named workloads
  `benign-read`, `injection-shaped`, and
  `hallucinated-reference` run end to end through
  `HearthProposer` + `run_task` against the labelled
  `ReplayTransport`, reusing P-4's fixture bundle and
  journal-folded `aggregate_stats`. Every replay number is
  labelled **REPLAY ONLY** forever: it measures the parser
  and the loop, never the model or the Hearth path.
- **Live mode** (gated on `SI_P5_LIVE=1`, mirroring P-4's
  gate): runs the preflight (below) first; only on a pass
  does it run P-4's live fixture suite and fold its stats.
  Rows are promoted only by a reviewer — the harness never
  promotes its own labels.

Replay exercise results (this slice's own run; REPLAY ONLY):
5 gateway calls, 5 parses, parse rate 0.8, stage-4
reference-error rate 0.2 (1 of 5 — the hallucinated-reference
workload, whose refusal then halts proposing:
`proposer-exhausted`), verdicts ADMIT 3 / REJECT 1, tasks
completed 2 of 3, injection proposals naming
`shell_exec`/`code_exec` 1, **executions of injected
intents 0**, journal growth per task median 9 entries.
These numbers describe the SI-side loop on scripted
responses. They are not model or node numbers.

### 2. Hardening — preflight + environmental-failure journaling

Motivated directly by P-4's evidence (SI-67 doc): the node
was lost mid-slice and the one live attempt died at
served-model discovery with connection refused, leaving **no
journaled record in any bundle** — the failure lived only in
a log file. In `si/gaia/live.py`:

- `preflight_live(...)` — a readiness check running the
  three legs in order (inference-base discovery →
  served-model discovery → residency poll naming the fleet
  model), returning the observed facts or raising a
  **stage-labelled** `DiscoveryError`
  (`[stage=discovery|served_models|residency]`); transport
  exceptions are wrapped into the same labelled shape.
  Fail-closed: readiness is never assumed from a partial
  pass, and no port is ever guessed.
- `journal_environmental_failure(...)` — journals a
  `gaia_environmental_failure` experience
  (`measurement_taken: False`, `tasks_run: 0`) so an
  environmental failure is a walkable journal record, not a
  partial run dressed as a measurement. The harness's live
  mode journals it into its measurement bundle and reports
  status `environmental_failure` with N=0; **no fixture
  task runs**.

### 3. Hardening — the manifest re-anchor P-4 was missing

Found while building this slice, from P-4's own code path:
`live.py` journaled residency/operator-act records into the
fixture bundle between tasks, but `run_task` begins with
`load_bundle`, which **fails closed** when the manifest
journal anchor does not match the journal tip. Had the node
stayed up, P-4's first `run_task` would have raised
`TamperError` on the anchor. `live.reanchor_bundle(...)`
applies the project's established pattern (the seam ingest
in `si/gaia/seam.py`: `_anchor_checkpoint` +
`_write_manifest`) after out-of-loop journaling, and
`_poll_and_journal` now calls it. The harness's replay path
uses it the same way.
