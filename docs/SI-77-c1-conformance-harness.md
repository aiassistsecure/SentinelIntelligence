## 1. What was built

- `si/gaia/conformance.py` — the harness:
  - `validate_corpus(corpus)` — §3.3 (1)–(5) as code. A
    corpus missing any requirement scores nothing; the
    record states **INSUFFICIENT CORPUS**, names each missing
    requirement, and publishes no rate.
  - `score_corpus(corpus)` — every scored response through
    `parse_proposal` (no parser change), folded per §3.2:
    `parse_ok` counts exactly `stage_reached == 6` with
    `failing_stage is None`; the rate is the exact fraction
    plus decimal; the failing-stage histogram (stages 1–6)
    carries the stage-1 count separately; per-workload,
    per-cycle, and (where items carry one) per-run breakdowns
    ride along; diagnostics (batch sizes and signal kinds
    among parse-ok responses, stage-4 reference behaviour,
    non-JSON plain-text body count) are reported, never
    substituted for the metric. Transport failures are
    unscored and never enter N.
  - `build_conformance_record(corpus)` — the §3.4 record:
    fingerprint (SI commit, parser identity, corpus id +
    hash, candidate label, environment, date
    America/New_York, `mode: offline`); honesty labels
    verbatim (§0) with `live_attempts: 0`; corpus section
    (per-workload counts, cycle coverage, signal
    elicitation, per-item provenance); results with each
    counted outcome walkable item by item (item id, parser
    outcome in the parser's own vocabulary, response hash —
    the body itself is held once in the corpus, never
    repeated in the record, §3.3(5)); `rows_18_1` exactly
    as SI-75 left them, each noted as promoted by none of
    this; `readiness: {threshold: null, unlocks: []}`.
  - `si74_harness_corpus()` / `si70_scripted_corpus()` —
    the harness-check corpus (§2) and the refusal fixture
    (§3). A CLI (`python -m si.gaia.conformance
    --si74-harness-check --out <dir>`) regenerates the
    shipped record; it refuses every other mode — no
    candidate is named (D-C3 is Mark's), so no other
    exercise ships.
- `tests/test_gaia_conformance_c1.py` — new tests pinning
  the metric, the histogram, the §3.4 record shape and
  honesty labels, the §3.3 refusals, and the SI-74 harness
  check (§2/§3 numbers).
- `docs/SI-77-measurements.json` — the harness-check
  record, generated by the CLI above from the code in this
  slice (fingerprint names main tip
  `c90669449f35759228d73cb7183dad9a8f1ae2ae`, the commit
  this slice branches from).
